The Workflow Tool

Summary — The Workflow tool runs a JavaScript program that controls many agents. The program starts agents, runs them at the same time, and collects their results. The tool runs in the background. You get a message when it is complete.

1 · What the tool is

The Workflow tool is a program runner. You give it a short JavaScript program. This program is the script.

The script starts agents. An agent is a copy of Claude that does one task. The script can start many agents at the same time.

Use a workflow for large tasks. Examples: a full code review, a large search, or a migration of many files.

2 · How to start a workflow

The tool call has five possible inputs. Use one of the first three. The other two are optional.

InputFunction
scriptThe full script as text. Use this for a new workflow.
scriptPathThe path of a script file on the disk. Each run writes its script to a file. To change a workflow, change this file. Then start the tool again with this path.
nameThe name of a saved workflow. The tool finds the script for you.
argsData for the script. The script reads this data from the args value. Use it for paths, questions, or configuration.
resumeFromRunIdThe identifier of an old run. The tool continues that run. See section 7.

The tool starts and gives back a task identifier immediately. The workflow then runs in the background. Type /workflows to see its progress.

3 · The script header

Each script must start with a header. The header is a simple object. It must not contain variables or calculations.

export const meta = {
  name: 'review-changes',
  description: 'Review the changed files',   // shown to the user
  phases: [
    { title: 'Find' },
    { title: 'Verify' },
  ],
}

The name and description fields are mandatory. The phases field is optional. Phase titles in the header must be the same as the titles in the script.

4 · Script commands

The script is standard JavaScript. It has seven special commands. Open each item to see the details.

agent(prompt, options) start one agent

This command starts one agent. The agent does the task in the prompt. The command gives back the agent's result.

If you give a schema, the agent gives back structured data. If you do not, the agent gives back text.

const result = await agent('Find the bugs in src/', {
  schema: BUG_SCHEMA,
})
pipeline(items, stage1, stage2, …) the usual choice

This command sends each item through all the stages. Each item moves at its own speed. Item A can be in stage 3 when item B is in stage 1.

This is the fastest shape for work with more than one stage. Use it as the default.

parallel(tasks) wait for all

This command runs all the tasks at the same time. It stops and waits until all the tasks are complete. This wait can make the workflow slow.

Use it only when a later stage needs all the results together. Example: remove duplicate findings before an expensive check.

A task that fails gives back null. Remove the null values before you use the results.

workflow(name, args) run a child workflow

This command runs a different workflow inside this one. The child uses the same limits and the same token budget. Only one level of children is permitted.

phase(title) and log(message) show progress

phase puts the agents that follow into a named group. The user sees this group in the progress display.

log shows a short message to the user immediately.

args input data

This value holds the data from the args input of the tool call. It can be a list, an object, or a simple value. Use it to configure a saved workflow.

budget token limit

The user can set a token target. Example: the user writes "+500k" in the prompt.

The script can read this target. budget.total is the target. budget.spent() is the quantity used. budget.remaining() is the quantity that remains.

The target is a hard limit. When the budget is empty, new agents do not start.

while (budget.total && budget.remaining() > 50_000) {
  // start more agents
}
!
The script must not use Date.now(), Math.random(), or new Date(). These functions break the resume function. Send times into the script through args.

5 · Agent options

Each agent() call can have these options. All of them are optional.

OptionFunction
schemaA JSON Schema. The agent must give back data that obeys this schema. The tool does the validation. Bad data causes an automatic retry.
labelA short name. The user sees it in the progress display.
phaseThe name of a progress group for this agent. Use this inside a pipeline.
modelA different model for this agent. If you do not set it, the agent uses the session model. This is almost always correct.
effortThe thinking level: low to max. Use low for simple tasks. Use a high level for hard checks.
agentTypeA special agent type. Example: code-reviewer.
isolationSet to worktree to give the agent its own copy of the repository. Use this only when many agents change files at the same time. It is expensive.

6 · Limits

  • Approximately 10 to 16 agents run at the same time. More agents wait in a queue.
  • One run can start a maximum of 1000 agents.
  • One pipeline or parallel call accepts a maximum of 4096 items.
  • The maximum script size is 512 KB.

7 · Stop and resume

To continue a workflow after a stop, do these steps:

  1. Stop the run, if it is active.
  2. Change the script file, if a change is necessary.
  3. Start the tool again with scriptPath and resumeFromRunId.

The tool keeps the results of the completed agents in a journal file. Agents with no changes give back their old results immediately. Only new or changed agents run again.

8 · Patterns

These shapes are not built in. They are good designs that you can put together in a script.

PatternFunction
Adversarial verifyStart three agents to attack each finding. If most of the agents reject the finding, remove it.
Judge panelMake N independent solutions. Score them with judges. Keep the best one.
Loop until dryStart search agents again and again. Stop when two rounds in sequence find nothing new.
Multi-modal sweepStart agents that each search in a different way. One search method does not find everything.
Completeness criticStart one last agent. It asks: "What is missing?" Its answer becomes the next round of work.

9 · Permission rules

A workflow can start many agents. It can use many tokens. For this reason, Claude must not start one without your agreement.

You give your agreement in one of these ways:

  • Write the word ultracode in your prompt.
  • Ask for a workflow in your own words. Example: "use a workflow".
  • Use a skill that starts a workflow.
  • Ask for a saved workflow by its name.

Without your agreement, Claude will describe a possible workflow. It will then ask you before it starts.
